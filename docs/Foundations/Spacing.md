# Spacing

## Purpose

Spacing defines the visual rhythm of the Design System.

It provides a reusable spacing scale used across layouts, components and analytical visualizations.

Spacing tokens should be used instead of hard-coded values whenever possible.

---

## Principles

- Use a limited spacing scale.
- Prefer spacing tokens over hard-coded values.
- Reuse existing spacing tokens before creating new ones.
- Introduce new spacing values only when justified by a real design need.
- Keep horizontal and vertical rhythm consistent across the system.

---

## Token hierarchy

The Design System currently defines one level of spacing tokens:

Primitive tokens

Primitive tokens represent physical spacing values (pixels) without any semantic meaning.

Example:

space-2
space-8
space-10
space-12

As the Design System evolves, semantic spacing tokens may be introduced when multiple components share the same design intention.

---

## Notes

The spacing scale is intentionally small during the initial phase of the Design System.

New tokens are introduced only when required by real components, avoiding unnecessary complexity and maintaining a coherent spacing system.
